# Question 1: QA Responsibilities in Each SDLC Phase

## 1. Requirement Analysis

- Review and analyze requirements for clarity, completeness, and testability
- Identify potential quality risks early
- Define acceptance criteria and quality metrics
- Participate in requirement walkthroughs to ensure understanding
- Create initial test plan and strategy

## 2. Design

- Review technical and functional design documents
- Ensure testability of design components
- Identify which test types will be needed (unit, integration, performance, etc.)
- Design test scenarios and test cases based on design specifications
- Validate that quality assurance requirements are addressed in the design

## 3. Development

- Perform code reviews to ensure coding standards and quality
- Guide developers on unit testing best practices
- Verify that unit tests are written and passing
- Set up test environments and test data
- Begin preparing test scripts and automation frameworks

## 4. Testing

- Execute planned test cases (functional, integration, system, performance, security)
- Log, track, and verify defects
- Perform regression testing after bug fixes
- Conduct user acceptance testing (UAT) coordination
- Generate test reports and quality metrics
- Sign off on quality before release

## 5. Deployment

- Perform smoke testing after deployment
- Validate production environment readiness
- Conduct post-deployment testing to verify functionality
- Monitor for issues in the live environment
- Create and execute rollback plans if needed

## 6. Maintenance

- Handle production bug reports and triage issues
- Perform regression testing for patches and updates
- Monitor system performance and quality metrics
- Maintain and update test cases and automation scripts
- Continuously improve QA processes based on lessons learned

# Question 2: Why QA Should Be Involved Early

## 1. Cost Efficiency

Defects found in requirements cost ~10x less to fix than those found in production. Early involvement prevents expensive rework.

## 2. Defect Prevention vs. Detection

QA prevents bugs from being written rather than just finding them later. They catch unclear, conflicting, or untestable requirements before coding begins.

## 3. Better Testability

QA ensures requirements and designs are testable from the start, preventing untestable features and enabling comprehensive test planning.
